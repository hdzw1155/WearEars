# README 修改计划（供审核，2026-11-07）

## 目的与当前状态

以当前代码和 [滚动反馈与驱动核查记录](scroll-and-driver-review.md) 为依据，更新项目首页，让普通用户看懂功能与适配范围，让接手 AI 按正确的驱动契约继续维护。

本文件是待审核计划。本轮没有按此计划改写 README，没有提交或推送 GitHub。发布版本、Release 附件和真机状态应在实际审核、发布时核实，不能把本地构建当成已经上线。

当前实现基准：0.4.0，保留 0.3.5 三套主要布局；滚动条按用户最新反馈再次调整为系统默认宽度参照、青蓝/少量蓝紫/冰白的滑块内部渐变、明显弹性；仅表圈产生微震与边界强反馈，手指滑动和停手不补震。最新构建、320 项离线检查和 APK 签名校验通过，尚未完成本轮装表对照。

推荐的用户功能措辞（实施时可按首页篇幅合并）：

> **滚动与表圈反馈**：主页和设置页共用圆弧滚动条，导轨与滑块同粗，参照设备默认尺寸。滑块内部呈现青蓝、少量蓝紫与冰白渐变，随滚动位置换色，并带有弹性拉伸和回弹。仅转动表圈时提供轻短微震，触顶、触底时加重；手指滑动和停手不补震。当前调整尚待 Galaxy Watch7 真机对照。

> **电量显示与缓存**：按具体耳机提供的数据显示左右耳、充电盒或整机电量。未上报的数据不猜测，保留最近确认的电量供磁贴查看；重新打开应用或主动刷新时查询状态。充电状态仅在驱动有可靠数据时显示。

## 四、开发者规范：必须同步修正的旧说法

| 原有说法 | 修改方向 | 理由 |
| --- | --- | --- |
| “重连策略归 UI 管” | 改为 `HeadsetController` 统一管理连接、重试、前台查询与磁贴操作。 | 当前 UI 和磁贴已共享控制器，不能引导新 AI 再写一套重连。 |
| “没有能力就不会调用 query/set” | 写清：写操作按能力门控；只读查询允许用于确认尚未知的能力；不支持的 query 方法仍需安全空实现。 | 按旧说明给 query 一律加能力守卫，会造成首包丢失后功能永久无法确认。 |
| “回调都在后台线程” | 改为驱动回调线程可能不同；通过控制器交给 UI 的事件统一在主线程处理，应用会话代数隔离迟到回调。 | 现有驱动、系统广播和 Profile 回调并非同一线程来源。 |
| “适配只需一个文件+一行注册” | 改为通常实现 `TwsClient` 并注册；必要的型号匹配、独立解析器、协议证据和测试一并提交。 | 简化宣传容易诱导把认证、分帧与线程代码堆进一个大类，或漏掉匹配边界。 |
| “不支持的操作，如华为通透” | 删除过时型号举例，改成“已确认不支持的操作给出明确失败结果；未知状态不冒充成功”。 | 华为实现已有通透，旧举例与当前功能冲突。 |
| “断开后停掉所有线程” | 改成取消排队、延时与重试，关闭资源；阻塞系统调用依赖关闭通道结束，不能保证任意调用立即退出。 | 避免把线程中断写成强制终止 I/O。 |

架构图补充：`MainActivity / ModeCyclerService → HeadsetController → 各驱动`；`TileStore / TileSnapshot` 保存确认状态与临时目标；六条直接写入驱动使用 `ProtocolWriter`；Sony/Technics 使用现有 `RfcommClient`，RoseLink 保留自己的写线程。

不要写“全部驱动共用同一个写线程”。`ProtocolWriter` 是复用的实现，每个活动连接拥有自己的队列。

保留并补全编译要求：UTF-8、Java 8、显式匿名内部类；禁止 Lambda、方法引用、`var`、`java.util.function`。保留无 Gradle 的构建方式。
