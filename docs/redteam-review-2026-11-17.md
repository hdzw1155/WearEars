# 2026-11-17 审计复核与修复交接

本轮以本仓库当前工作区为准，包含另一位开发者已完成的新 UI；不从旧审计副本覆盖源码。Git 基点仍为 `b1bec9d`，存在此前和本次的未提交修改，不能把工作区等同于该提交的发布包。没有安装设备、改版本号、提交或推送。

用户已明确选择 **A：锁定时允许调小、禁止调大，70% 保留再次确认**。新 UI 的布局、颜色资源及 Neo 绘制实现保留。共享控件只修改必要的触控和生命周期逻辑。

## 本轮改动

1. **音量规则贯穿真实触控入口。** `VolumeGuard` 在锁定时允许降低；`VolumeBarView` 支持锁定状态下点低位或横向拖低，旧至上画布支持锁定状态下向左拖低。长按解锁的那次手势仍不能调音量，纵向滑动仍交给页面。70% 重新锁定；降回阈值以下会重新建立高音量保护。系统档位只有一档时，第二次确认仍能进入高档，不是永久锁死。
2. **系统音频查询集中到 `AudioConnections`。** 标准驱动、自动选择和磁贴共用一次性 A2DP/HFP/LE Audio 查询；超时、权限不足和完整的否定结果分开处理，迟到代理也关闭。标准驱动监听 Profile 变化，不再把 ACL 已连接直接当作音频已连接；一个 Profile 断开后仍检查其他有效音频连接。活跃控制器独立监听 ACL 断开，移除磁贴也不影响主页断连处理。
3. **自动选择优先使用当前已连接的已配对耳机。** 只有自动模式查询系统连接；用户手动指定地址保持固定。查询结果带控制器会话代数，页面退出、切设备后到达的结果不启动旧连接。磁贴操作仍固定到其设备地址。
4. **同设备短暂回退时保留降噪候选位置。** 标准驱动回退仅把同地址曾确认过的 ANC 作为候选，不提升当前写入能力；未知名称不覆盖已有名称。换设备仍清除旧状态，不能将历史能力当作当前协议确认。
5. **修复报文重同步。** vivo 改用可独立测试的有界流解码器，保留半包和粘包，坏头不吞后续真头。NiceHCK、OPPO 提前排除非法头字段。Rose 校验失败时寻找已通过校验的内嵌候选帧，保留原有坏包后恢复能力；不能简单全部改成 `drop(1)`。
6. **非法参数在解析边界拒绝。** 多品牌解码器对 null 和超出数组长度的 count 返回空结果，不修改半包状态；载荷解析返回未知。编码器及小米鉴权对非法参数明确抛出 `IllegalArgumentException`。这属于调用边界加固，不意味着蓝牙对端能发送 Java null 指针。
7. **收紧旧磁贴入口。** `ModeCyclerActivity` 不再读取外部控制参数，只请求更新磁贴并打开现有主页。删除不再使用的 `ModeCyclerService` 及其 manifest 声明。新磁贴继续通过受绑定权限保护的 `TwsTileService` 和 `LoadAction` 操作，不需要页面跳转。宿主仍缓存旧布局时，旧按钮会进入主页，待新布局刷新后恢复磁贴内操作。
8. **修补控件与窗口生命周期。** 音效选项松手吸附与程序选中使用一致的 padding 坐标；主页、设置页持有并在销毁时关闭对话框，音效面板暂停时关闭其确认框。没有新增页面或通知。
9. **明确控制器边界。** 单例创建加同步并安全发布；磁贴操作入口允许从其他线程投递到主线程。实际驱动仍每次连接创建新实例，不复用已断开的裸驱动对象。没有因报告的错误线程假设重写整个状态机。
