## 二、需要优先与正文对齐的地方（建议，尚未改稿）

1. 第五章“在2026年已突破58%” → “Counterpoint于2025年6月预计，HLOS智能手表出货占比将在2026年超过58%”。同时注明HLOS并非均能运行本项目。
2. 第五章“海外Wear OS占27%” → “Counterpoint于2024年4月预计，Wear OS在2024年中国以外高阶智能手表市场的份额达到27%”。若想保留2026年市场判断，应换较新实绩资料。
3. 第二章、第五章“其余51.2%全部由独立声学品牌构成” → “前五以外品牌仍占据较大市场空间”；具体份额先补原表，独立声学品牌份额另需分类统计。
4. 第五章由CIRP与华为30%直接推出“绝大多数Wear OS用户异品牌配对” → 保留两项各自样本范围，再写“这些资料提示跨品牌组合存在，但Wear OS与耳机配对比例仍需专项调查”。
5. 第六章将第三方方案统称需要Root → 分别列HyperEars、LibrePods的系统与功能条件。
6. 第四章Fitts公式归属 → 增补MacKenzie来源，说明采用常用Shannon形式；Hick“大幅增加”改成条件与对数关系的准确描述。
7. 第一章“全球智能手表年出货约1.6亿” → 当前列入的文献未定位到直接支持该数字及其年份、口径的公开原表；应补明确来源或暂不使用这个数值。
8. 第十二章MIT、GPL、清洁室、官方授权 → 分开写公开许可事实、实际开发过程和未来授权计划。原始许可并不自动证明本项目已经合规，也不支持GPL禁止商业使用的推论。

## 三、书目整理建议

- [5]补2025-03-31发布日期；机构作者写法可以保留，但应全表统一机构作者与个人作者的选择规则。
- [9]作者按页面补齐SINGH B、JAIN A，日期可保留2025-06-16。
- [20]、[22]、[23]使用官方页面实际题名，避免把自行概括当作正式题名；[13]等仓库描述性副标题也应采用一致规则。
- Android开发文档与GitHub文档具有动态性。新增核验对应2026-11-07；不将原稿所有[2026-11-04]直接改成今天，也不声称本次见到的内容就是11月4日的历史内容。最终确认引用内容后登记实际查阅日期，GitHub尽量锁定提交或发布版本。
- 正文以机构—年份写法引用，文末又采用顺序编号；部分数字缺少精确引文定位。建议最终统一引用体例，把重要数字就近对应到具体条目和统计期。
- 商业计划书可以使用行业报告、开发文档和开源仓库，不必为了形式增加无关论文。优先修正预测/实绩、统计分母和样本外推，比增加文献数量更有价值。

## 四、本次核验的边界

25条均已逐项查找；大部分可读到公开原文或官方文档。Counterpoint完整付费报告、CIRP付费部分、两篇早期论文全文未取得。[18]采用公开研究文献记录交叉确认，不能称为通读原始全文。[6]只核验了所列转载页，未取得Canalys原报告。[7]独立发布日期栏仍应留存确认。[8]具体品牌份额表未定位。

因此，可以说“文献来源大多能查到，已逐条记录支持范围与缺口”；不能说“25条原始全文全部核实无误”或“正文所有结论都有充分证明”。本报告与上一轮42项建议有重叠，属于参考文献专题补核验，不将重叠项重复计为新增正文改动。
