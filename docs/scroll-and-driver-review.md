## 本次范围

按用户最新要求实施：保留 0.3.5 的三套页面布局与 0.4 功能，调整侧边滚动条、三星风格滚动震感、设置页指示条和极简音量条，并核查全部已注册驱动。

## 滚动条与触感

| 项目 | 实现 |
| --- | --- |
| 线宽 | 导轨和滑块同粗；读取设备默认主题的 `android:scrollbarSize`，未指定时使用 `ViewConfiguration.getScaledScrollBarSize()`，替代过细的固定 1.35dp。没有叠加会扩大外观线宽的粗光晕。 |
| 颜色 | 按用户再次确认使用青蓝、少量蓝紫、冰白。渐变绑定滑块自身，短滑块内部也能显示多个颜色；滚动位置改变时移动色带。 |
| 设置页 | 使用与主页相同的 `ArcIndicatorView`，固定在滚动容器之外，不拦截点击和表圈事件。 |
| 显隐 | 滚动时提亮，停手 850ms 后用 220ms 淡回原有静止亮度；恢复明显的弹簧追随、长度拉伸及 420ms 衰减回弹。 |
| 绘制 | 缓存滑块局部的多段渐变，以复用矩阵移动颜色；每帧绘制导轨和滑块各一次。颜色和透明度不再互相覆盖。 |
| 内容变化 | 监听视口与内容布局，音量显示、能力确认、语言与样式变化后同步滚动范围。 |
| 微震 | **仅表圈**按实际滚动位移累计，每 8dp 产生一个候选微震，反馈间隔至少 28ms。优先采用硬件支持且时长不超过 20ms 的低频 `LOW_TICK`，强度 0.30；否则回退为低振幅短包络。合并输入不补发积压震动。 |
| 撞墙 | **仅表圈**滚动实际到达顶/底时触发一次强反馈；已在边界继续向外滚动时也能触发。优先使用支持且不超过 70ms 的 `THUD`，否则用 21ms 强包络。边界锁避免持续重复强震，同时触发滑块的弹性视觉反馈。 |
| 强弱衔接 | 强反馈后至少 120ms 不插入微震，避免立即被下一次微震覆盖。 |
| 系统触感 | 不再使用上一版默认滚动 tick / focus / limit 或预设 click。使用触感用途的振动属性，遵循系统触感开关。硬件不支持振幅控制时，仅能用短/长脉冲区分强弱，不能宣称能控制低频。 |
| 原有交互 | 保留表圈目标累加、惯性、阻尼、触摸接管和橡皮筋回弹。**手指拖动、手指甩动和停手不补震**。 |
| 生命周期 | 页面暂停、窗口失焦时清理自有帧任务、延时震动与形变；返回同步位置，静止时没有常驻动画循环。 |
| 音量条 | 极简音量填充改为 `#4CC38A`，与正常电量条一致；经典和液位配色保持原有实现。 |

本轮根据用户实际反馈纠正了过细、炫彩不明显、回弹偏弱和震动类型不合要求的问题。粗细使用设备系统默认尺寸作参照，目前未逐像素对照三星设置页，也未在 Galaxy Watch7 上比较修正后的马达强弱、声音或主观绵密感，因此不能标记为“已经与三星原装完全一致”。硬件能力、系统版本与触感设置会影响最终体验。

主要文件：`ArcIndicatorView.java`、`ScrollIndicatorMotion.java`、`AppScrollView.java`、`ScrollFeedback.java`、`VolumeBarView.java`、`SettingsActivity.java`、`MainActivity.java` 和 `res/layout/activity_settings.xml`。Java 文件均位于 `src/com/hdz/wearcontrol/` 或其子目录。新增的动效类被现有滚动条实际使用，没有新增页面或未启用视图。

## 本次修正的跨驱动问题

1. **界面线程发送蓝牙数据。** 漫步者、原道、华为、小米、OPPO 的延时查询会进入同步写入；vivo 调试入口也可能在界面线程发包。本次让这六条驱动的底层写入使用共用的 `ProtocolWriter` 实现。每个活动连接复用一个工作线程，待发送任务上限 32；满队列会报告错误，断开后清理旧排队任务。保留各品牌原有封包与字段。
2. **旧连接读取与新连接混淆。** 为直接读取 socket 的驱动补充读端身份检查，读取使用本次 socket 引用，取消后的读循环不关闭随后创建的新 socket。关闭 vivo socket 后同时清理引用，避免已断开仍被当作连接正常。
3. **非标准模式残留旧高亮。** 连接控制器与磁贴存储现在接受接口规定的 `-1` 未知模式。漫步者抗风噪、原道已知特殊模式、华为非标准模式不会继续冒充上一个三挡状态。界面继续使用原有三挡，未知状态清除已确认高亮；待确认目标与真实状态分开，磁贴乐观刷新保留。
4. **未知模式误判切换成功。** 模式确认必须是合法目标挡位；刷新操作的 `-1` 目标不能与未知回报相等后误判为一次模式切换成功。确认等待期间收到不同挡位或未知状态会撤销旧的成功延时，界面也不对未知回报播放“切换成功”反馈。
5. **能力过度声明。** 华为、OPPO、原道、vivo 的 ANC 改为合法模式回报确认后开放；vivo 空间音频和 DeepX 同样由有效回报确认。只读查询不受“尚未确认能力”的门控，连接初始化和原有刷新流程继续查询，避免首包丢失后锁死可用功能；写操作仍受能力门控。能力变化会更新界面和磁贴。
6. **验证等级过度声明。** vivo 只有已登记的 Air3 Pro 型号名称标记为本项目实测；华为收紧为明确的 FreeBuds 6i 名称。其他候选不再因为含品牌词就继承这些型号的实测等级。
7. **vivo 响应缺少校验。** 新增在驱动中实际使用的 `vivo/VivoProtocol.java`，核对成功状态、长度、百分比、三挡枚举、空间开关与 DeepX 值。合法 0% 保留，FF 部件保持未知，未知充电扩展位不覆盖正常电量。错误状态不再当作电量或成功模式发布。

`ProtocolWriter` 负责排队和取消；已经进入系统的阻塞 I/O 仍依赖关闭 socket/GATT 结束。不能把线程中断描述为可以强制终止任何系统蓝牙调用。

## 已记录但未宣称修复的风险

- **多设备自动选择：** 未手动选择地址时，注册表仍主要按已配对集合顺序找候选；两副已配对、只有一副在线的选择需要实测。手动选择继续严格使用指定设备。
- **运行时降级：** `createFallback()` 并不代表私有驱动失败后自动降级；控制器当前仍采用有限重试原驱动的策略。是否增加降级以及如何显示状态属于后续行为选择，本次未暗中切换到另一套连接策略。
- **同连接快速 A→B→A：** 连接代数能隔离旧连接，但部分协议状态回报没有请求身份。迟到回报是否提前确认最新目标，需要可控回调顺序和真机记录进一步验证。
- **Sony/Technics 共用传输：** 协议 Handler 同时执行写入、解码与部分超时任务，系统写入长时间阻塞时的超时与接收排队压力尚未模拟。新 `ProtocolWriter` 不替换这两条已有传输。
- **缓存新鲜度：** 保留用户接受的最近电量缓存。一个部件更新不代表其他部件同时更新；目前全局成功时间并非逐部件更新时间。

这些项目是核查范围中的待验证项，不应在后续说明中改写成“全部耳机驱动都已正常”。

## 真机验收清单

1. Galaxy Watch7 上对照系统设置长列表的粗细。仅在转动虚拟表圈时检查低沉细密微震、顶/底强反馈及强震不被立即打断；手指慢拖、甩动与停手应保持无补震。
2. 连续快速转动后停手，确认没有补发积压震动；在边界持续同向转动，确认不反复强震；离开后再次抵达仍有反馈。
3. 三套主页与设置页分别检查顶部、中部、底部，圆弧不截断、不压文字；从设置按钮开始拖动仍能接管滚动，按钮点击与音量横向拖动正常。
4. 极简音量条为电量绿色；经典/液位音量显示、系统音量同步与单一设置入口保持正常。
5. 切后台、灭屏、打开弹窗后，自有装饰动画和延时震动停止；回到页面位置正确。
6. 逐型号记录手表系统、耳机固件：首次打开同步、重进、连接中退出、蓝牙开关、出盒入盒、手机占用、多点连接、耳机按键改档与连续点击磁贴。
7. 漫步者切到抗风噪时清除旧确认高亮；切回三挡可以正常确认。确认新目标仍即时乐观高亮，失败/超时不会变成伪成功。
8. 无 ANC 设备不出现假降噪能力；空间音频与 DeepX 在有效回应后可用，已有 Air3 Pro 功能逐项复测。

## 资料依据

- 先前各品牌参考资料与抓包索引见 [协议验证记录](protocol-validation.md)，资料中的外部项目实测不等于 WearEars 本轮实测。
- vivo 电量与三挡 payload 对照原始维护者的 [Air3 Pro 实机记录](https://github.com/silverpoetry/HyperEars/blob/main/docs/vivo-tws-air3-pro-protocol.md)。空间音频和 DeepX 继续沿用本项目既有记录，没有新增猜测命令。
- 低频微震与冲击的原语定义见 [VibrationEffect.Composition](https://developer.android.com/reference/android/os/VibrationEffect.Composition)；实际使用前按 [Vibrator](https://developer.android.com/reference/android/os/Vibrator) 查询支持情况和时长。
- 默认滚动条尺寸的读取依据 [ViewConfiguration](https://developer.android.com/reference/android/view/ViewConfiguration)，使用该尺寸不等于已测量三星设置页自身的定制控件。
- 透明度修正依据 [Paint.setColor / setAlpha](https://developer.android.com/reference/android/graphics/Paint)：颜色赋值包含 alpha，不能先设透明度后再用不透明颜色覆盖。
