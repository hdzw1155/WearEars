# 本轮工作经验

更新：2026-11-18。适用于会话状态、磁贴、音量安全和可选模块的后续维护。

1. **先分清页面跳转与布局重排。** 磁贴点后退出不一定是高度变化：LaunchAction 即使启动的是秒退 Activity，也改变了宿主页面状态。刷新或切档用 LoadAction，打开应用才用 LaunchAction；同时检查能力首包是否令卡片消失。
2. **“还不知道”不是“不支持”。** 驱动的当前能力和候选能力分开。首包延迟时保留待确认区域；只有已确认能力可写。对已明确不支持 ANC 的型号，候选能力也必须排除 ANC。
3. **实时会话、历史缓存、点击目标是三种数据。** 断线清空实时值；保留历史用于标明时间的缓存；pending 到期只能撤销，不能写成 confirmed。缓存电量和最近同步时间均不能证明当前连接。
4. **副作用要绑定设备，并处理重复请求。** 磁贴宿主可能重发 lastClickableId，旧布局也可能在设备切换后仍存在。使用设备地址、渲染代数和消费记录，重绘不能重复发送控制命令。
5. **防误触应放在唯一写入口。** 各种界面可以有不同画法和手势，系统音量写入只能经过同一个 VolumeGuard。长按解锁与调节不能在同一次触摸里发生；阈值按实际系统档位向下取整。
6. **有效回包比固定等待更可靠。** 切换后屏蔽四秒回包会丢掉最快的正确确认。用会话代数、目标和新回包处理确认；成功 ACK 不一定含状态，必要时只读查询补确认。
7. **型号相近不代表协议相同。** Xiaomi Buds 5 Pro 不等于 Redmi Buds 5 Pro；盒电量缺失也不能由耳机电量补齐。先确认端点、帧、型号和原始回包，再写解析器和设置命令。
8. **模块化要证明可以删。** 字符串注册能解除编译硬依赖，但 manifest、XML、自定义 View 和调试 receiver 也要检查。裁剪验证不使用完整编译产物作为 classpath，也不复用上次验证目录。
9. **压缩要保留反射入口和序列化字段。** R8 下类名可读不代表反射字段不会被删除。必须同时核对模块构造器、XML/manifest 组件、protobuf 编码和 APK 签名。JVM 检查需要 JDK 类库；测试编译可使用原 API 声明，运行必须只加载压缩结果，防止旧库掩盖缺失。
10. **验证结论要限定范围。** 离线报文测试说明解析与状态规则，SDK 编译说明构建兼容，JVM 检查说明压缩后入口与序列化；它们都不能替代 Watch7 上的磁贴宿主行为、固件兼容、声音效果和实际耗电测试。
11. **并行开发先明确文件和接口归属。** 新 UI 由另一位 AI 负责时，收尾不顺手调整其布局或清理其未完工代码。交接当前状态读取、动作分发和音量唯一写入口；集成时按接口修改，避免用旧的整份 Activity 覆盖已完成的逻辑修复。

临时查阅资料和修改脚本放在项目 `scripts/`，完成后删除；保留可复用的构建与回归脚本。交接记录写清未完成的型号能力和发布状态，避免下一次把“有协议线索”误写成“已支持”。

## 2026-11-17 审计复核补充

12. **审计条目是待验证的问题，不是源码事实。** 先定位正式工作区、实际依赖和调用路径，再评价报告。此次 Tile 依赖已把请求投递到主线程，`apply()` 的内存更新也不是异步；不能根据不适用的线程前提大改控制器。对外测试必须断言正确行为，不可不论成功失败都累计“已复现漏洞”。
13. **音量规则要同时验证保护器和手势入口。** 只修改 `VolumeGuard` 允许降低，控件如果仍吞掉所有锁定触摸，用户照样无法调小。横向调节、纵向页面滚动、长按解锁后的同次手势、阈值二次确认和降低后重新保护都需单独考虑。此轮按用户选择允许锁定调小；不能把先前全锁设计直接标作 bug。
14. **坏包恢复策略取决于协议。** 不能把所有失败都换成逐字节丢弃：Rose 的载荷可含帧头字节，盲目 `drop(1)` 会将坏帧内部的电量字节误认成新头，反而卡住后续有效帧。此次先遇到旧回归失败，再改为只接纳通过校验的内嵌帧，兼顾旧恢复路径与新增重叠帧用例。
15. **ACL、系统音频和私有控制是不同连接。** 系统标准驱动必须以 Profile 查询为依据；A2DP 断开时 HFP 可能仍连着。同地址真实存活的私有控制通道则可支持音频留在手机的场景。统一查询要关闭迟到代理、区分超时未知与完整否定，并在断开事件后排除系统暂时保留的旧 Profile 状态。
16. **自动选择设备也属于异步会话。** 已连接设备优先只适用于自动模式；显式指定的地址不可被“智能选择”覆盖。查询回调必须比较会话代数，退出页面、换设备或磁贴目标失效后不能再建立旧连接。
17. **历史能力只能稳定显示，不能授权写入。** 同设备回退到标准驱动时可保留曾确认的降噪候选位置；当前会话未确认能力仍不可发降噪指令。未知名称不能覆盖已知名称，换地址时不能继承旧设备的电量和能力。
18. **兼容入口也要写明退化方式。** 旧导出 Activity 无法鉴别外部控制参数是否来自旧磁贴；收紧后让旧缓存打开控制页，新 LoadAction 继续在磁贴内完成操作。删除闲置服务时一并更新 manifest、模块裁剪脚本和 README，不留下虚假的架构说明。
19. **协作基线应持久保存。** 另一位开发者在同一工作区改 UI 时，文件归属和改前校验值应保存在项目内的临时产物目录；不能依赖可能跨轮失效的工具内存。空基线与当前哈希比较不能证明文件发生变化，更不能据此回退别人的新界面。

20. **把松手当成一次位置采样。** 从 0 右拖不一定收到中途 MOVE，最后一帧也可能只在 UP。用起点到终点的位移区分点锁、拖动和纵向滚屏；CANCEL 不能提交。回放应穿过真实 View 和音量写入口，并模拟系统没有接受设置时的回读。
21. **部分回包证明通道仍活着。** 等不到 ANC 时保留已回报的电量，只补查缺项；完全沉默的会话才重建一次。驱动给出的未知模式和旧设备缓存都不能算作本次读取成功。
22. **协作回退要保留改前内容。** 哈希可以证明一致，不能恢复未提交内容。只保存、比较自己要改的部分；若另一位开发者随后更新了布局，不用旧基线覆盖。图像方案先留在 `docs/`，实时数值和点击行为不能烘进运行时位图。
