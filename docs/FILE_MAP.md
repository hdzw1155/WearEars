# WearEars 文件导航与改动指南

本文给下一位维护者或接手 AI 使用。所有链接均以本文所在的 `docs/` 为相对起点，文中命令在仓库根目录运行。

## 先跟一笔“从磁贴切换降噪”与“主界面改写扩展特性”

1. **磁贴入口**：[TwsTileService](../app/src/com/hdz/wearcontrol/TwsTileService.java) 收到点击请求后，[TileLedger](../app/src/com/hdz/wearcontrol/TileLedger.java) 消费一次性令牌，[TileActions](../app/src/com/hdz/wearcontrol/TileActions.java) 绑定设备地址与令牌，服务校验当前版本免责、实际链路和有效点击后交给协调器。门禁拦截的旧点击在同意后仍保持失效。
2. **核心协调与事务**：[ControlHub](../app/src/com/hdz/wearcontrol/ControlHub.java) 将三档降噪交给 [Transactions](../core/src/com/hdz/wearcontrol/Transactions.java)，将通用扩展特性（`ANC_LEVEL`、`TRANS_MODE`、`LOW_LATENCY`、`FIND_MY_BUDS` 等）交给按通道隔离的 [FeatureTransactions](../core/src/com/hdz/wearcontrol/FeatureTransactions.java)，并由 [ConnectionOwner](../app/src/com/hdz/wearcontrol/ConnectionOwner.java) 管设备选择、连接代次与重试。
3. **驱动会话与传输**：[DriverRegistry](../app/src/com/hdz/wearcontrol/DriverRegistry.java) 匹配品牌工厂，[WireSession](../app/src/com/hdz/wearcontrol/WireSession.java) 为本次连接创建独立线程与端口，驱动按品牌协议走 RFCOMM 或 GATT 完成探测、写出与解码。
4. **状态回报与快照**：[SessionReports](../app/src/com/hdz/wearcontrol/SessionReports.java) 绑定会话代次与写出证据，[DeviceState](../core/src/com/hdz/wearcontrol/DeviceState.java) 保存已确认状态、特性表、佩戴状态与固件文本，[TileStore](../app/src/com/hdz/wearcontrol/TileStore.java) 与 [TileState](../app/src/com/hdz/wearcontrol/TileState.java) 驱动磁贴渲染。
5. **复现定位顺序**：连续点击/迟到回包先看 [CoreChecks](../tests/CoreChecks.java) 与 [FeatureEngineChecks](../tests/FeatureEngineChecks.java)；品牌时序看 [WireChecks](../tests/WireChecks.java) 及对应 `*ExtChecks.java`；RFCOMM/GATT 与平台回调看 [RfcommChecks](../tests/RfcommChecks.java) 与 [PlatformChecks](../tests/platform/com/hdz/wearcontrol/PlatformChecks.java)。

## 私有协议与证据分级

- **历史实机基线**：旧版在所列机型上验证过基础连接、电量与三档降噪/基础音效。
- **开源资料扩展 / 实验性**：Wave 3/5 按公开资料新增的扩展特性与实验品牌，均需经真机固件验证；关键禁发命令已在编码层硬拦截。

## 构建与测试入口

`build.py test` 会自动编译并运行 `tests/` 下全部 `*Checks.java`（含后续新增测试类），再执行 `tests/platform_checks.py`。

| 我要验证什么 | 命令与测试文件 |
|---|---|
| 纯核心规则 | `py -X utf8 build.py core`：[CoreChecks](../tests/CoreChecks.java) 覆盖选机、主事务、GATT 发送泵、免责与风格迁移。 |
| 音量护栏、通用特性与 Wave 1 驱动修复 | `py -X utf8 build.py test`：[AuditRegressionChecks](../tests/AuditRegressionChecks.java)（`VolumeGuard.observe` 与空地址归一）、[FeatureEngineChecks](../tests/FeatureEngineChecks.java)（特性引擎与查找耳机安全车道）、[Wave1DriverFixChecks](../tests/Wave1DriverFixChecks.java)。 |
| 既有协议向量与驱动线序 | 同一 `test` 命令：[ProtocolChecks](../tests/ProtocolChecks.java)、[WireChecks](../tests/WireChecks.java)、[RfcommChecks](../tests/RfcommChecks.java)。 |
| HMOV 与其余五品牌扩展协议 | 同一 `test` 命令：[VivoExtChecks](../tests/VivoExtChecks.java)、[HuaweiExtChecks](../tests/HuaweiExtChecks.java)、[XiaomiExtChecks](../tests/XiaomiExtChecks.java)、[OppoExtChecks](../tests/OppoExtChecks.java)，以及 Wave 5 的 `tests/OtherBrandsExtChecks.java`（NiceHCK/Edifier/Sony/Technics/RoseLink）。 |
| 双耳 HRTF 声学内核 | 同一 `test` 命令：[SpatialDspChecks](../tests/SpatialDspChecks.java) 验证 ITD 极性/精度、Brown-Duda ILD、耳廓切迹、FDN 衰减、10 秒 360° 扫频零 NaN/峰值限幅与立体声交叉馈送。 |
| 平台回调、双语对等与标准蓝牙刷新 | `py -X utf8 tests/platform_checks.py`：检查 226 项 ZH/EN 字符串键对等，再用 SDK 34 编译生产适配器并运行 [PlatformChecks](../tests/platform/com/hdz/wearcontrol/PlatformChecks.java) 与 [StandardRefreshChecks](../tests/platform/com/hdz/wearcontrol/StandardRefreshChecks.java)（含 [MemorySettings](../tests/platform/com/hdz/wearcontrol/MemorySettings.java) 与 [tests/platform](../tests/platform) 测试替身）。 |
| APK 构建、驱动裁剪与依赖校验 | `py -X utf8 build.py verify`（全量测试 + 签名对齐校验）或 `py -X utf8 build.py apk --drivers none` / `--drivers vivo,huawei`。离线依赖哈希见 [SHA256SUMS](../vendor/SHA256SUMS)，脚本入口为 [build.py](../build.py) / [build.bat](../build.bat)。 |
